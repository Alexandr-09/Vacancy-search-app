## 1. Як запустити проєкт

Для запуску проєкту потрібен будь-який локальний вебсервер (через використання ES6-модулів `import`/`export` запуск через подвійне клацання по `index.html` блокується політикою CORS у браузері):

### Варіант 1. Через VS Code (найпростіший)
1. Встановіть розширення **Live Server**.
2. Натисніть правою кнопкою миші на файл `index.html` **«Open with Live Server»**.

### Варіант 2. Через Node.js (npx)
1. У терміналі папки проєкту виконайте команду:
   ```bash
   npx serve .
## 2. Які кейси враховано та як їх реалізовано
 - Порожній результат пошуку / відсутність вакансій:
    -Якщо за обраними фільтрами чи пошуковим запитом нічого не знайдено, замість сітки відображається зрозуміле повідомлення для користувача («За вашим запитом вакансій не знайдено»).   
#### Синхронізація зі станом URL (Deep Linking & History):
  - Усі обрані фільтри (запит, місто, зарплата, чекбокс «Віддалено», сторінка) зберігаються в URL-параметрах (URLSearchParams) через history.pushState.
  - При перезавантаженні сторінки або поширенні посилання всі фільтри та форма відновлюються автоматично.
  - Підтримано коректну роботу кнопок браузера «Назад / Вперед» через обробник події popstate.
#### Захист від некоректних або відсутніх даних з API:
  - Додано перевірки для відсутніх полів (наприклад, якщо назва компанії чи міста відсутні, виводяться дефолтні значення).
  - Якщо відсутній аватар/логотип компанії, автоматично генерується стильна плашка-аватар із першою літерою назви компанії.
#### Блокування пагінації:
  - Кнопки «Назад» та «Вперед» стають неактивними (disabled), коли користувач перебуває на першій або останній сторінці відповідно.

## 3. Що свідомо не було зроблено та чому
  - Повноцінний збережений стан "Обраного" (LocalStorage / Backend):
    - Наразі переключення сердечка на картці змінює стан тільки в межах поточного відображення. Збереження в localStorage або відправка  запиту на сервер свідомо не реалізована, оскільки API працює в режимі Read-Only  і не підтримує авторизацію користувача.
## 4. Де відбувся відхід від макета Figma та чому
  - Гнучкість розмірів та аватарок:
    - Якщо у Figma розміри та логотипи компаній були статичними зображеннями, у коді реалізовано динамічний fallback-компонент (ініціали на кольоровому тлі) на випадок, якщо API повертає вакансію без логотипу.
    - Адаптивні відступи та тач-зони:На мобільних версіях трохи збільшено висоту інпутів та кнопок до 44px для відповідності стандартам Web Accessibility (зручність натискання пальцем на смартфонах).
    - Кастомний чекбокс:Чекбокс «Віддалено» стилізовано через CSS (appearance: none) замість стандартного браузерного, щоб він повністю відповідав гайдам та колірній гамі з макета Figma (#D81B60).
